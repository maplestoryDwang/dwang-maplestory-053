============================================================
 GMS053 服务端  一键编译启动  使用说明
============================================================

一、怎么用
------------------------------------------------------------
1. 先运行 step1db，把 MySQL 装好、数据库导进去
   （库名 dwang053，账号 root，密码 root）。
2. 再进 step2，双击 start.cmd，等着就行。

第一次运行会自动做四件事：
   (1) 从 GitHub 把代码拉下来，放在 step2\source
   (2) 用包里自带的 JDK 21 加 mvnw 编译出服务端 jar
   (3) 把客户端插件和汉化数据同步到 step3client\origin-client
       （插件 = Hook.dll / Launcher.exe / 中文文本表；数据 = 汉化过的 wz / img）
   (4) 启动服务端

以后要更新，再双击一次 start.cmd 就行：它会重新拉最新代码、重新编译、
顺手把客户端插件 / 汉化数据更新到最新，再启动。

【老包一次性升级】如果你手上这个包的 start.cmd 还没有"更新客户端"这一步
（窗口里看不到 [3/4] 那一行），那它自己不会升级自己。先照上面跑一次 start.cmd
把代码拉到最新，然后双击一次：

   step2\source\doc\升级脚本.bat

它会把这个包里的 start.cmd 换成新版（旧的备份成 start.cmd.old）。
以后就全自动了，不用再跑它。


二、文件都是干什么的
------------------------------------------------------------
start.cmd             唯一的入口。双击 = 拉代码 + 编译 + 启动
config.cmd            所有配置都写在这里（仓库地址、分支、数据库、内存……）
source\               自动拉下来的代码。不要手动改，更新时会被覆盖
source\client-dist\   客户端插件 + 汉化数据的发布载荷（plugin\ 是插件，data\ 是汉化 wz/img）
                      脚本会把它同步到 step3client\origin-client，见第五节
jdk-21.0.2\           包里自带的 JDK 21，客户不需要自己装 Java
PortableGit\          包里自带的 Git，客户不需要自己装 Git
application.yml       客户要改数据库相关的设置，改这个文件
application-prod.yml  数据库连接（默认 dwang053 / root / root）
launch.bat            旧脚本，直接跑自带的 Maplestory053.jar，不编译，留着备用


三、start.cmd 的几种用法
------------------------------------------------------------
在 step2 目录的地址栏里输入 cmd 回车，然后：

   start.cmd            拉代码 + 编译 + 更新客户端 + 启动   （最常用，也是双击的效果）
   start.cmd check      只检查远端有没有新版本（不拉代码、不编译）
   start.cmd update     只拉取 / 更新代码
   start.cmd build      只编译（不碰 git）
   start.cmd client     只更新客户端插件 / 汉化数据
   start.cmd run        只启动（不编译、不更新客户端）


四、更新检查与版本信息
------------------------------------------------------------
双击 start.cmd 之后，它会先用 git ls-remote 问一下远端——只查不下载，
一次往返几 KB，不会再像以前那样每次都把代码拉一遍。然后分三种情况：

1) 已经是最新
      已经是最新版本：24a5748 (2026-09-24)
   直接往下走，不白下载。

2) 远端有新版本 —— 会停下来问你
      本地版本 : 4edb2d1 (2026-09-23)
      远端版本 : 24a5748
      版本来源 : 主地址
      [Y] 更新      [N] 不更新
   * 选 N，或者 20 秒内没按键，就用本地这个版本直接启动，下次再说
     （无人值守也不会卡住）。
   * 想改等待秒数：config.cmd 里的 UPDATE_WAIT
   * 想不问了、有更新就自动更新：config.cmd 里 UPDATE_ANSWER=Y

3) 连不上远端
   只警告一句，用本地现有版本照常启动，不影响你玩。
   （主地址不通会自动切备用地址；两个都不通还会去掉 git 全局代理再试一遍。）

每次检查完都会在本目录刷一份 版本信息.txt（GBK 编码，记事本直接打开就正常）：

      本地版本 : 4edb2d1 (2026-09-23)
      本地提交 : 4edb2d18ce6aefc7fa6f212e043db7e12948fa2c
      远端版本 : 24a5748
      远端提交 : 24a57480309eea853e3f402104103de9d4ed0f7a
      版本来源 : 主地址
      当前状态 : 远端有新版本，本次没有更新（还在用本地这个版本）

同目录的 更新日志.md 是仓库里 doc\update_log.md 的副本，每次更新代码后自动刷新。
注意它反映的是【你本地这份代码】的日志；想知道远端新版改了什么，得先更新下来才能看到。

只想看看有没有更新、不拉代码不编译：start.cmd check

五、要改配置怎么办
------------------------------------------------------------
用记事本打开 config.cmd，改完保存即可。常用的几项：

   GIT_URL            仓库地址（默认 GitHub）
   GIT_URL_BACKUP     备用地址：GitHub 拉不动时自动改用它，填 Gitee 地址即可
   GIT_BRANCH         分支，默认 master
   GIT_DEPTH          1 = 只拉最新一版，下载量最小；0 = 拉完整历史（2GB 以上，很慢）
   GIT_PROXY          git 用的代理，例如 http://127.0.0.1:7890，不用就留空
   UPDATE_MODE        reset = 强制和远程一致（推荐）；pull = 只做快进合并
   JDK_DIR            用哪个 JDK，默认包里自带的
   MAVEN_CLEAN        1 = 每次先清理再编译（干净）；0 = 增量编译（快）
   SPRING_PROFILE     默认 prod
   USE_EXTERNAL_YML   1 = 启动时读外面的 application.yml
   SAVE_LOG           1 = 运行日志同时写文件；0 = 只在窗口里显示
   CONSOLE_CHARSET    控制台字符集，中文 Windows 保持 GBK
   LOG_CHARSET        server.log 的字符集，默认 UTF-8（改 GBK 则老记事本可直接打开）
   JAVA_RUN_OPTS      启动内存，例如 -Xms512m -Xmx2g，留空则用 JVM 默认值（推荐）
   SYNC_CLIENT        1 = 拉代码后顺手更新客户端插件 / 汉化数据（默认 1）
   CLIENT_DIR         客户端目录；留空自动找 step3client\origin-client，放别处就写绝对路径
   CLIENT_SYNC_DATA   1 = 连汉化 wz / img 一起更新（默认）；0 = 只更新插件
   SYNC_CLIENT_STRICT 1 = 找不到客户端目录就停下来；0 = 只警告，服务端继续启动（默认）
   CHECK_UPDATE       1 = 启动前先查远端有没有新版本（默认）；0 = 不查，每次直接拉最新
   UPDATE_WAIT        发现新版本时等你按键的秒数，超时按「不更新」处理（默认 20）
   UPDATE_ANSWER      ask = 弹窗问你（默认）；Y = 有更新就自动更新（无人值守用）；N = 永不自动更新
   GIT_TRY_NO_PROXY   1 = 主/备地址都不通时，去掉 git 全局代理再试一遍（默认 1）
   VERSION_FILE       版本信息文件名，默认 版本信息.txt
   CHANGELOG_FILE     更新日志文件名，默认 更新日志.md


脚本自己升级的时候，config.cmd 是【自动合并】的：新版的结构和新增项照抄过来，
你自己改过的值（代理、客户端路径、内存参数……）原样保留，旧的备份成
config.cmd.bak-<时间戳>。所以放心改，改过的不会被冲掉；
如果你一项都没改过，那就等于直接换成新模板。

六、客户端插件 / 汉化数据怎么更新（重要）
------------------------------------------------------------
插件和汉化数据不用手动拷：它们跟着服务端代码一起发布，位置是

   source\client-dist\
      plugin\   插件本体（Hook.dll、Launcher.exe、中文文本表…）
      data\     汉化数据（wz\String.wz、Data\Quest\Say.img …）
      tools\    同步脚本（更新客户端.bat / sync-client.ps1）

每次跑 start.cmd（或者 start.cmd client）时脚本会：
   1. 自动找客户端目录——默认找 <包根>\step3client\origin-client，
      找不到才问你（这个包的结构就是这样，一般不用管）；
   2. 按文件指纹对比，只覆盖变化的那几个（插件只有几百 KB，几秒钟）；
   3. 覆盖前把旧文件备份到 客户端目录\_backup_client\<时间>\，只留最近 5 份；
   4. 更新完在客户端目录写一个 .gms053-client.txt，记录当前装的是哪一版。

不会动的东西：
   * config.ini（你在里面写了服务器地址）——【自动合并】：新版的结构和新增项照抄，
     你改过的值原样保留，旧的备份成 config.ini.bak-<时间戳>；
   * 客户端目录里其它文件（插件只认 client-dist 清单里列的那些）。

客户端放在别的地方怎么办：
   方法一：在 config.cmd 里写死
             set "CLIENT_DIR=D:\games\origin-client"
   方法二：手动跑一次，把路径当参数
             source\client-dist\tools\更新客户端.bat "D:\games\origin-client"
           脚本会把找到的路径记在 source\client-dist\client-dir.txt，以后自动用。

只想看会改哪些文件、不动文件：
   source\client-dist\tools\更新客户端.bat -DryRun
   （还有 -Verify 只校验、-NoData 只更新插件不动 wz）

这一条失败不影响服务端：脚本警告一句就继续启动，下次运行再试一次。
常见失败原因：
   * 游戏/启动器正开着——文件被占用，先关掉游戏；
   * 客户端主程序和发布版本不一致——会警告（插件是针对特定客户端版本逆向的），
     想让它直接拒绝更新，把 source\client-dist\client-dist.txt 里的 client_exe_strict 改成 1；
   * 找不到客户端目录——见上面"客户端放在别的地方怎么办"。


七、为什么 jar 不从 target 里拷出来（重要）
------------------------------------------------------------
服务端启动时，wz、wz-zh-CN、scripts、scripts-zh-CN 这些资源都是按
「当前工作目录」去找的，不是按 jar 所在位置找。

所以脚本的做法是：不复制 jar，而是先把工作目录切到

   source\gms-server\gms-handler

然后直接运行同目录下 target\Maplestory053.jar。

好处是每次重新编译出来的新 jar 都能立刻用上，不会出现
「jar 更新了、资源目录还是旧的」这类问题。源包里的 wz 和脚本也是同一份。


八、启动成功后长什么样
------------------------------------------------------------

九、日志和排错
------------------------------------------------------------
运行日志：
   窗口里会实时打印；
   同时还会写一份到 source\gms-server\gms-handler\logs\server.log
   （不想让它写文件，就把 config.cmd 里的 SAVE_LOG 改成 0）

关于中文显示（乱码就是这里的问题）：
   中文 Windows 的控制台代码页是 936(GBK)，脚本启动时会把它固定成 936。
   而 Spring Boot 3 的控制台日志默认按 file.encoding(UTF-8) 输出，
   两边对不上，中文日志就会变成「姝ｅ湪鍚姩」这种乱码。
   脚本里已经用 CONSOLE_CHARSET=GBK 把日志也按 GBK 输出，所以窗口里是正常的。
   server.log 仍然是 UTF-8，用 VS Code / Notepad++ / 新版记事本打开都正常；
   想用老记事本直接双击打开，就把 LOG_CHARSET 改成 GBK。

常见问题：

1) 卡在拉代码 / 报网络错误
   → GitHub 在国内经常连不上。把仓库同步一份到 Gitee，然后在 config.cmd 里填
     GIT_URL_BACKUP=https://gitee.com/你的用户名/dwang-maplestory-053.git
     如果你本机有代理，也可以填 GIT_PROXY=http://127.0.0.1:7890

2) 报数据库连不上
   → 先确认 step1db 已经执行过，MySQL 正在运行。
     默认连的是 localhost:3306/dwang053，账号 root，密码 root。
     要改就改 step2\application-prod.yml。

3) 编译失败
   → 先看日志里第一处 error。内存不够时先执行：
        set MAVEN_OPTS=-Xmx1024m
     再跑 start.cmd build。
   → 第一次编译要下载 Maven 和几百 MB 依赖，慢是正常的。

4) 提示端口被占用
   → 说明已经有一个服务端在跑了，先把它关掉，或者改配置里的端口。

5) 想停止服务端
   → 在运行窗口里按 Ctrl+C，或者直接关掉那个窗口。

6) 控制台中文是乱码
   → 说明控制台代码页和日志输出的字符集不一致。
     脚本默认已经处理好了；如果你手动改了 chcp 或 CONSOLE_CHARSET，把两者对齐即可
     （控制台 936 就配 GBK，控制台 65001 就配 UTF-8）。

7) 更新客户端失败 / 提示找不到客户端目录
   → 看第五节的"客户端放在别的地方怎么办"：手动跑一次带路径的
     更新客户端.bat，或者在 config.cmd 里写 CLIENT_DIR。
     游戏开着时文件会被占用，先关游戏。想看细节就加 -DryRun 先空跑一遍。

8) 报 detected dubious ownership
   → 一般不会遇到，脚本里已经加了 safe.directory 处理。
     如果你手动敲 git 命令遇到了，可以把 source 目录加到 git 信任列表：
        git config --global --add safe.directory <source 的完整路径>
     （把包放在 exFAT / FAT32 格式的移动硬盘上时，最容易出这个问题）


十、给维护者：要换仓库 / 换分支
------------------------------------------------------------
只改 config.cmd 两个变量就行：
   GIT_URL       换成新仓库
   GIT_BRANCH    换成新分支
source 目录里已经有旧仓库时，脚本走的是
   git fetch <地址> <分支>  然后 reset --hard
所以换了地址也能直接更新过去，不需要把 source 删掉重拉。
（注意 reset 会丢弃 source 里的本地改动，这是故意的：客户机要保证和远程一致。）
