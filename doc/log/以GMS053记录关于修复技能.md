# 以GMS053记录关于修复技能

关于玩家的技能释放：

服务端需要处理的包头有几种：

1. *SPECIAL\_MOVE BUFF类*

2. 攻击类

- *UserMeleeAttack 近战攻击*

- *UserShootAttack 远程攻击*

- *UserMagicAttack 魔法攻击*

3. 召唤兽相关包头



buff类，可以分成大致三类：

1. 给自己的buff

2. 给怪物的debuff

3. 地图放置类 mist



BUFF的效果不光服务器需要保存当前的状态，同时还需要把状态告诉给客户端。除了把CD告诉给客户端以外，还需要把BUFF的状态也告诉给客户端。

1. 给自己的buff涉及org\.gms\.client\.BuffStat。包含给自己的buff和debuff。给自己的BUFF和SkillId是绑定的。

2. 给怪物的Debuff涉及org\.gms\.client\.status\.MonsterStatus。MonsterStatus包含给怪物的Debuff和怪物自己加的Buff。

通过不同的mask进行控制。这个mask的作用：

1. 服务端自己保存状态，以便于对角色的各种信息能够及时更新、定时任务取消buff等。

2. 告诉客户端当前角色的状态，客户端可以根据不同的状态释放不同的技能、或者显示不同的数值。

例如：英雄的回声```*`ECHO_OF_HERO`*`(1L << 48)``，正确的mask，客户端就能正常显示buff的数字,否则只是服务端自己加了数值，客户端没有显示增加。

例如：圣骑士要释放技能```*`属性攻击(1211002)`*```需要服务端告诉客户端当前角色有```*`WK_CHARGE`*`(1L << 22)``的状态，也就是释放过*烈焰之剑、寒冰之剑等*，否则客户端无法释放这个技能。

当然也有特殊案例，部分BUFF不会显示在面板上：弓箭手火眼晶晶添加的伤害百分比直接显示在打出的伤害上面，而不在面板上显示。

在方法``org.gms.server.StatEffect#loadFromData``就定义了每个职业技能可以附加上去的状态，这个状态能不能正常显示看的是客户端能不能正常解析出来的前提。



举例：*SEAL 封印状态*

在BuffStat 中：  *SEAL*\(1L \<\< 19\),  表示怪物给人物上的封印效果，发包是*GIVE\_BUFF*\(0x3A\), // 给予角色Buff

在MonsterStatus *SEAL*\(1 \<\< 10\), 表示人物给怪物上的封印效果，发包是*APPLY\_MONSTER\_STATUS*\(0x9A\),



发包的内容都类似：

```Java
public static Packet giveBuff(int buffid, int bufflength, List<Pair<BuffStat, Integer>> statups) {

    final OutPacket mplew = OutPacket.*create*(SendPacketOpcode.*GIVE_BUFF*);
    long mask = *getLongMask*(statups);
    mplew.writeLong(mask);
    for (Pair<BuffStat, Integer> statup : statups) {
        mplew.writeShort(statup.getRight().shortValue());
        mplew.writeInt(buffid);
        mplew.writeInt(bufflength);
    }

    mplew.writeShort(0);
    mplew.write(0);         
    return mplew;

}
```

把mask都拼接起来，然后发给客户端

```Java
private static <E extends LongValueHolder> long getLongMask(List<Pair<E, Integer>> statups) {
    long mask = 0;
    for (Pair<E, Integer> statup : statups) {
        mask |= statup.getLeft().getValue();
    }
    return mask;
}
```

核心encode的代码：

```Java
for (Pair<BuffStat, Integer> statup : statups) {
        mplew.writeShort(statup.getRight().shortValue());
        mplew.writeInt(buffid);
        mplew.writeInt(bufflength);
    }
```

在其他端里面代表的就是：nOption\(short\)、rOption\(int\)、tOption\(int\)

nOption：代表这个BUFF的值，有一些是持续时间，有一些是其他

rOption：代表skillID

tOption：代表持续时间



不同的版本mask值会有一些差异，不过差异不大，可以通过自己枚举尝试找到。



## 特别注意

给客户端发的状态包的动画效果和实际的技能ID并不是完全耦合的，当然也不是完全不相干，如果这个技能没有这个mask的处理，就不会有动画展示

举例：牧师的巫毒术：*DOOM（2311005）实际要给客户端发的mask是：DOOM\(1 \<\< 16\),*

```Java
case Priest.*DOOM*:
    monsterStatus.put(MonsterStatus.*DOOM*, 1);
```

告诉客户端把mob变成蓝蜗牛。

如果发的skill是2311005，但是mask是BLIND\(1 \<\< 12\)，则怪物不会变成蓝蜗牛，而是被致盲了，大幅度减小物理伤害。



利用这个原理，我们可以保留原本的功能，用另一个技能的特效，修复原本有问题的技能：

1. 狂乱之剑/斧的黑暗效果

2. 龙咆哮的眩晕效果
