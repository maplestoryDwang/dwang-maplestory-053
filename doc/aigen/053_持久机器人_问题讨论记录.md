## 无真人客户端时的怪物控制、受击与恢复

| 日期 | 状态 | 影响范围 |
| --- | --- | --- |
| 2026-11-24 | 待客户端分析与游戏内验证 | 1.3 战斗与生存、1.4 恢复、1.8 整体联调 |

当前机器人 Backend Client 没有游戏连接，发给它的地图包会被丢弃。服务端代码中，地图可把怪物控制权分配给场内角色，而真人客户端通过 MOVE_LIFE 上报怪物移动，通过 TAKE_DAMAGE 上报角色受击。持续恢复也有来自真人客户端的 HEAL_OVER_TIME。有真人进场时，控制权和上报来源可能变化，无法单凭旁观画面判断地图只有机器人时的行为。

### 待核对

- 在 053 客户端的 IDA 工程可用后，对照怪物控制权、怪物移动、角色受击和持续恢复的发送与接收入口。记录哪些值由客户端生成，哪些状态由服务端计算，以及动作、事件和计时的边界。
- 区分怪物巡逻、索敌、追击、接触伤害、技能伤害、死亡与控制权转移。对照 Java 的 MapleMap、Monster、MoveLifeHandler、TakeDamageHandler 和 HealOvertimeHandler。
- 确认道具椅、地图椅和自然恢复各自的恢复来源。有服务端恢复任务时，要保留原有结算并检查是否重复。
- 评估由服务端为无连接角色补足控制、受击与计时的方式。真人和机器人同图时，同一只怪物在任一时刻只使用一个控制来源，控制权转换时能继续运行。

### 验收

1. 让机器人独自进入有怪地图，无真人在线旁观。通过服务端状态或日志验证怪物能移动、追击，角色会受伤并按规则死亡和复活。
2. 让真人短暂进入再离开，核对怪物控制权转换时的位置、仇恨和伤害事件。检查是否出现静止、重复攻击或重复伤害。
3. 分别测试自然恢复、道具椅和地图椅，核对恢复节奏与数值。用同配装真人客户端对照。
4. 在可用测试环境中由开发侧执行检查，记录角色、地图、配置、观察窗口、对照结果与服务端日志。
