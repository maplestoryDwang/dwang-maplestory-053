## 十二、进图闪退排查与修复（2026-10-23）：`ToolTip` 节点

### 现象

进入本批地图（702000000 嵩山镇 / 702010000 / 702020000 / 702050000 / 702090101 英语村等）时，客户端弹错 **-2147467261**（`0x80004003` E_POINTER）后闪退；服务端没有任何报错。
老图（500000000 水上市场、701010000、701010323）和本批的 **701010324 可怕的山丘**都能正常进。

### 排查过程（每步排除一个方向）

1. **资源完整性**：24 张图的客户端 img 与 `cms059` 原文件 md5 一致；tile/obj/back/bgm/地图标记/NPC/怪物/String 引用逐条解析 **0 缺失**；`hook_crash.log` 里 `[UiLayout] MISSING WZ RESOURCE` 一条都没有 → 不是缺资源。
2. **resman 日志**（`config.ini` 里 `DebugFileAccess=true`）：进图时所有文件都 `ok`，最后停在最后一只怪物/NPC 的 img 之后，之后再没有任何文件被打开 → 崩溃发生在“文件都加载完之后”的进场逻辑里。
3. **IDA 分析**（`client-plugins\ida\GMSv53.exe.i64`）：异常抛在 `0x4CDEB8`（`CField::Init`）→ `0x4CE0AA` → `0x6BE054`，后者属于 `CUIToolTip` 家族（`CUIToolTip::MakeLayer` = `0x6BAEDA`）；`if (!a3) throw -2147467261` 命中 → **进场构造某个提示框时失败**。
4. **排除 NPC**：702020000 一个 NPC 都没有，照样闪退。
5. **排除汉化 hook**：`TranslateText=false` 照样闪退。
6. **排除地图名顺序**：`String/Map.img` 的 `china` 节点已按地图 id 升序重排（顺带整理，**不是病因**；其它 street 节点原本就有乱序，也能正常进）。
7. **对比北斗同图**：059 与北斗的 `702050000.img` 整树对比 4041 个节点，除 `miniMap/canvas` 像素格式（059 = ARGB4444、北斗 = ARGB8888）外完全一致。
8. **整批换北斗版**（24 图 + 7 素材，转 053 格式、画布 ARGB8888）：**仍然闪退** → 不是“059 vs 北斗”的版本差，也不是画布格式。
9. **排除 BGM**：把 702020000 的 `info/bgm` 改成能正常播的老曲目 `BgmCN/ShanghaiField` → 仍然闪退。
10. **切分服务端 / 客户端**：把客户端 `702020000.img` 临时换成**能进**的 `701010324.img`（059 原版）→ **能进，怪也能打死** → 服务端下发数据没问题，问题在客户端地图数据。
11. **节点二分**（保留掉线图其余节点，只换一个来源）：
    - `back` + 8 个图层 ← 能进的图 → 仍闪退
    - `foothold` ← 能进的图 → 仍闪退
    - **删掉 `ToolTip` 节点 → 能进** ✅

    能进的 701010324 本身**没有 `ToolTip`**；本批 24 张里 **21 张带 `ToolTip`**。

### 结论

053 客户端在本批地图的 `ToolTip`（地图内可点击提示框）数据上会 `throw E_POINTER`，在 `CField::Init` 构造提示框那一步直接终止客户端。
与版本来源、画布格式、BGM、foothold **都无关**；`ToolTip` 的字段结构（`x1/y1/x2/y2`）和能正常进的泰国图完全一样，具体触发条件没查到（泰国图带 `ToolTip` 却没事），因此按“可用优先”处理。

### 修复

- **客户端**：从 24 张图的 img 删除根节点 `ToolTip`（21 张有；701010324、702070300、702090400 本来就没有），已同步 `client-dist\data\Data\Map\Map\Map7`。
- **服务端**：从对应的 `wz\Map.wz\Map\Map7\*.img.xml` 删除 `ToolTip` 块（21 个文件），保持两边一致（服务端本来也不读这个节点）。
- **客户端地图与素材统一采用北斗转换版**：24 张图 + Tile `ShaolinCN1`/`ShaolinCN2`/`EnSchoolCN`、Obj `ShaolinCN`/`EnSchoolCN`、Back `ShaolinCN`/`EnSchoolCN`（画布 ARGB8888、img 头 `73f8fad9…`），与后续北斗来源的数据保持一致。

### 追加根因（同日第二轮）：北斗版地图的 `life` 引用了没迁的 NPC

第一轮删 `ToolTip` 后 702020000 能进，但 **702000000 仍闪退**。继续排查发现：

- 客户端会**按自己地图 img 里的 `life` 列表**去加载 NPC/怪物 img（不只是按服务端下发的列表）。
- 换成北斗版地图后，**北斗版 `702000000` 的 `life` 是另一套 NPC**：`9010000`、`9310082`、`9310084`、`9330078`、`9330090`、`9050007`、`9310100`、`9209103`，其中 **7 个客户端没有**（`9310082`/`9310084`/`9330078`/`9330090`/`9050007`/`9310100`/`9209103`）→ 加载失败 → 同样抛 `E_POINTER` 闪退。
- 059 版 `702000000` 的 `life`（17 NPC + 5 怪物）**全部存在**。

**最终方案**：客户端地图**回到 059 版**（只删 `ToolTip`），与服务端 XML、已迁的 059 NPC/怪物/任务/道具同源；7 个素材 img 保留北斗转换版（结构一致、引用全部解析通过）。
已用脚本逐个校验地图 `life` 引用：702000000（17 NPC / 5 怪）、702050000（1 / 11）、702090101（1 / 18）、702100000（5 / 0）**缺失 0**。

**两条根因都要记住**：① `ToolTip` 节点；② 地图 `life` 引用的 NPC/怪物必须在客户端存在。

进入 `702060000`（少林秘室）客户端立即闪退、没有错误提示；角色记录停在 `702100000`。同批其余 23 张图正常。

### 定位过程
1. **先排除地图数据**：客户端 `702060000.img` 与 059 原版逐节点比对，只少了 `ToolTip`；life（9600025 + 9310044）、obj（含本图独有的 `ShaolinCN/house16`、`trap/moving`）、back、tile、bgm（`shaolin_mishi`）、miniMap 引用**全部解析通过**。
2. **再排除缺资源**：`resman_trace.log` 里 `702060000.img → Obj/trap.img → Mob/9600025.img → String/Mob.img → Npc/9310044.img` 全部 `ok`，之后**没有再读任何文件** → 崩在“文件加载完之后的进场逻辑”，和 2026-10-23 的 `ToolTip` 那次同一类。
3. **排除插件**：`config.ini` 加 `WideBackFillBackmost.702060000 = 0` 关掉这张图的背景补铺，仍然闪退。
4. **换成正常怪图**：把客户端 `Data\Mob\9600025.img` 临时换成 `9600024.img`（普通怪）→ **能进** → 问题锁定在 9600025 这张怪图的数据。
5. **删两段攻击**：在真数据（技能等级已修 13/80）上删掉 `attack5`、`attack6` → **能进** → 实锤。

### 根因
053 客户端每条普通攻击动画都要按段号去动画名表 `g_aszMobAnimName` 取名字，而这张表里 **attack 只排了 4 段**（全服 `Mob.wz` 837 只怪里，4 段的只有 4 只，没有任何 5 段以上的怪）。

9600025 武林妖僧是从 059 / 083 迁过来的 150 级 boss，`attack1`–`attack6` 共 6 段。第 5、6 段取到的是**别的动画名**，随后去读该节点的 `info` 子节点得到**空指针**，客户端直接崩 —— 所以日志里既没有缺资源提示，也没有服务端报错。

### 修复
- **客户端** `Data\Mob\9600025.img`：删 `attack5`、`attack6`（2,597,585 → 2,070,592 字节）
- **服务端** `wz\Mob.wz\9600025.img.xml`：同步删这两段（保持两边一致；服务端不读攻击动画，但避免以后又从 XML 导回去）
- **发布**：`client-dist` 升到 **1.1.12**（tag `client-v1.1.12`），`client-dist.sha256` 已用 `make-manifest.ps1` 重算
- **备份**：`E:\game\ms\gms053\地图迁移\备份\20261031-141500-少林秘室闪退-9600025\9600025.img.orig-with-attack5-6`（改前原图）

### 教训
迁移怪物时**要数 img 里 `attackN` 的个数**：053 只认 1–4 段，超出的段不会报错、只会在进场建攻击动画时崩客户端。同理 `skillN`、`hitN`、`dieN` 这些按名字前缀索引的动画也要和本版本对得上。


## 十九、2026-10-31 嵩山镇 702000000 再次进图闪退：obj 索引断档

### 现象
10-24 删 life / 删 World Tour 牌子之后，进 `702000000` 客户端弹 **-2147467261**（`0x80004003` `E_POINTER`）闪退；`warp` 直飞、走传送口都一样。同期金庙 `501000000`、水上市场 `500000000`（同样删过 life）**能正常进**。

### 根因：删条目留下了索引断档
`702000000` 当时被删了三样东西，客户端 img 里就留下了空洞：

| 列表 | 原条目 | 删后 | 断档 |
|---|---|---|---|
| `3/obj`（第 3 层物件） | 0~16 | 0~13、15、16 | **缺 14**（删掉的 `guide/common/tour/0` 牌子） |
| `life` | 0~21 | 5~13、16~20 | 缺 0~4、14、15（5 只鬼 + 9000020 / 9310061 / 9330045） |

053 客户端遍历 **obj 列表是按索引连续取**（0、1、2…）的，缺号就取到空节点 → `CField::Init` 里抛 `E_POINTER` → 弹 -2147467261 退出。

**判据**（用 OrzRepacker 扫了全服客户端地图）：
- 其它 1500+ 张图，`obj` 列表**没有一张有断档**；
- `life` 断档却是常态：`501000000` 缺 8、`500000000` 缺 26，都能正常进 → **life 断档能容忍，obj 断档必崩**。

### 修复
1. 客户端 `702000000.img` 的 `3/obj`：删掉 14 后，把原来的 `15`、`16` 重命名为 `14`、`15`，索引恢复 **0~15 连续**；
2. `life` 维持 14 条（5~13、16~20，沿用删除后的断档，不影响）；
3. 顺带恢复 10-24 加的传送口：`h-top03`（x=3170, y=274）→ `701010600` / `xuzhou00`（059 原版这个口是死路）；
4. `client-dist` 升到 **1.1.13**，`client-dist.sha256` 重算。

**2026-10-31 验证通过**：客户端进 `702000000` 正常，右侧 `h-top03` 可到徐州平原3，地图上没有多余的幽灵和 NPC。

### 规则（以后照这个做）
- **删地图 `obj` / `back` / `tile` 条目后，必须把后面的索引重排成连续**，否则客户端进图就抛 `E_POINTER`（-2147467261）。
- `life` 删条目可以留断档（已验证 501000000 / 500000000）。
- 排查口诀：**进图闪退 + 弹 -2147467261 + 资源都齐 → 先查 obj 索引有没有断档**，再查多余的未知节点（ToolTip 那次是反过来的「多」）。

### 附：那两只"鬼"是什么
`9500196` / `9500197` 是少林活动用的**幽灵 / 透明幽灵**（等级 10、HP 10、经验 33，`info/summonType=1`）。
它们在地图 `life` 里是 `mobTime = 1800`，也就是 **1800 秒（30 分钟）刷新一次**；10-24 已从服务端 XML 和客户端 img 的 life 里一起删掉，所以现在不会出现（客户端 life 里即使留着条目，怪物也是服务端刷的，不会凭空冒出来）。
